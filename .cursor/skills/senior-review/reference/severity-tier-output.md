# Output schema: severity tier

Use these **headings exactly, in order** (claims-frontend family):

### Summary

2–4 sentences: scope, verdict (approve / approve with comments / request changes), biggest risk or strength.

### Scope reviewed

Bullet list of paths or “pasted snippet”.

### Blockers

Numbered. If none: `None.`

### Major

Numbered. If none: `None.`

### Minor

Numbered. If none: `None.`

### Nits

Numbered. If none: `None.`

### Suggested follow-ups

Optional ordered checklist for the implementer.

## Severity definitions

| Tier | Meaning |
|------|---------|
| **blocker** | Must fix before merge |
| **major** | Should fix |
| **minor** | Nice to have |
| **nit** | Style / preference |
